# 5. 类型系统

# 5. 类型系统

RHDL 的类型系统是整个语言安全性和可综合性的基石。它利用 Rust 的强类型机制，将位宽、方向、时钟域等硬件属性编码到类型中，使得许多硬件设计错误在编译期就被捕获。类型系统分为四大部分：**基础硬件类型**、**方向类型**、**复合类型**和**时钟域类型**。此外，RHDL 通过**多视图建模**将功能视图中的普通 Rust 类型与硬件类型分离，保证综合路径的严格性，同时允许功能模拟器使用更灵活的软件类型。

## 5.2 基础硬件类型

基础硬件类型对应硬件中的基本信号，位宽由 const 泛型参数 `N` 指定。

```mermaid
classDiagram
    class HardwareType {
        <<trait>>
        +width() usize
        +is_synthesizable() bool
    }

    class Bool {
        +width() = 1
    }

    class Bits~N~ {
        +width() = N
    }

    class UInt~N~ {
        +width() = N
        +arith_ops()
    }

    class SInt~N~ {
        +width() = N
        +arith_ops()
    }

    class Clock
    class Reset
    class Analog

    HardwareType <|-- Bool
    HardwareType <|-- Bits
    HardwareType <|-- UInt
    HardwareType <|-- SInt
    HardwareType <|-- Clock
    HardwareType <|-- Reset
    HardwareType <|-- Analog

```

*   `**Bool**`：单比特逻辑，等价于 `Bits<1>`，但语义上表示布尔值，支持逻辑运算 `&&`, `||`, `!`。
    
*   `**Bits<N>**`：原始 N 位向量，不解释为数值，仅支持按位运算 `&`, `|`, `^`, `~` 和移位。
    
*   `**UInt<N>**`：N 位无符号整数，支持算术运算 `+`, `-`, `*`, 比较运算等，也支持按位逻辑。
    
*   `**SInt<N>**`：N 位有符号整数（二进制补码），支持有符号算术和比较。
    
*   `**Clock**`：时钟信号，不参与数据运算，仅用于时钟域绑定。
    
*   `**Reset**`：复位信号，可配置极性，通常与 `ClockDomain` 关联。
    
*   `**Analog**`：模拟/三态信号，仅用于顶层 IO，不可在内部逻辑中使用。
    

### 5.2.1 位宽指定

位宽通过 Rust 的 const 泛型指定，例如 `UInt<8>` 表示 8 位无符号整数。编译器在编译期检查所有运算的位宽兼容性。

```mermaid
flowchart LR
    A[UInt<8>] -->|+ UInt<8>| B[UInt<8> 或 UInt<9>]
    C[UInt<8>] -->|+ UInt<16>| D[编译错误：位宽不匹配]

```

RHDL 默认采用**严格位宽规则**：算术运算结果的位宽与操作数相同，但允许显式扩展（`extend`）或截断（`truncate`）。

## 5.3 方向类型

方向类型包装基础类型，表示端口的方向。所有模块端口必须使用方向类型声明。

```mermaid
classDiagram
    class Input~T~ {
        +get() T
        +direction = In
    }
    class Output~T~ {
        +set(value: T)
        +direction = Out
    }
    class InOut~T~ {
        +drive(value: T)
        +read() T
        +direction = InOut
    }
    Input~T~ o-- HardwareType
    Output~T~ o-- HardwareType
    InOut~T~ o-- HardwareType

```

*   `**Input<T>**`：输入端口，只能读取，使用 `.get()` 获取内部信号。
    
*   `**Output<T>**`：输出端口，只能写入，使用 `.set(value)` 赋值。
    
*   `**InOut<T>**`：双向端口（如三态总线），仅允许出现在顶层模块，需要显式方向控制。
    

方向检查是编译期行为：

```mermaid
flowchart TD
    A[尝试将 Input 连接到 Output] --> B{方向匹配?}
    B -- 不匹配 --> C[编译错误]
    B -- 匹配 --> D[允许连接]

```

## 5.4 复合类型

复合类型用于组合多个信号，提供结构化描述能力。

### 5.4.1 Bundle（结构体）

`Bundle` 类似于 SystemVerilog 的 `struct`，通过 `#[derive(Bundle)]` 派生。字段可以是基础类型、方向类型或其他 Bundle。

```mermaid
classDiagram
    class DecodedInsn {
        +opcode: UInt~7~
        +rd: UInt~5~
        +rs1: UInt~5~
        +rs2: UInt~5~
        +funct3: UInt~3~
        +funct7: UInt~7~
    }
    class Bundle {
        <<trait>>
        +flatten() Vec~Field~
    }
    DecodedInsn ..|> Bundle

```

Bundle 可以整体连接，也可拆分访问字段。

### 5.4.2 Vec（数组）

`Vec<T, N>` 表示 N 个 `T` 类型的数组，映射为 Verilog 的 `wire [N-1:0]` 或多维数组。

```mermaid
classDiagram
    class Vec~T,N~ {
        +elements: [T; N]
    }
    Vec~T,N~ o-- T

```

数组索引必须是编译期已知的常量，用于生成多路选择器或存储器。

### 5.4.3 Mem（存储器）

`Mem<T, DEPTH>` 描述存储器，可以是同步或异步，通常映射为 FPGA 的 Block RAM。

```mermaid
classDiagram
    class Mem~T,DEPTH~ {
        +read(addr: UInt) T
        +write(addr: UInt, data: T)
    }
    Mem~T,DEPTH~ o-- T

```

存储器操作在组合或时序逻辑中使用，综合工具会根据访问模式推断 RAM/ROM 类型。

## 5.5 时钟域类型

时钟域类型显式管理时钟、复位和时序逻辑，确保寄存器与正确的时钟和复位信号关联。

```mermaid
classDiagram
    class ClockDomain {
        +clock: Clock
        +reset: Reset
        +polarity: Polarity
        +reset_kind: ResetKind
        +new(...) ClockDomain
        +set_polarity(...) ClockDomain
        +set_reset_kind(...) ClockDomain
    }
    class Polarity {
        <<enum>>
        ActiveHigh
        ActiveLow
    }
    class ResetKind {
        <<enum>>
        Synchronous
        Asynchronous
    }
    ClockDomain --> Polarity
    ClockDomain --> ResetKind

```

*   `**Polarity**`：复位极性，高有效或低有效。
    
*   `**ResetKind**`：复位类型，同步或异步。
    

寄存器通过 `ClockDomain` 绑定：

```mermaid
flowchart LR
    Reg[Reg<T>] -->|belongs to| CD[ClockDomain]
    CD -->|provides| Clk[Clock]
    CD -->|provides| Rst[Reset]

```

## 5.6 类型运算与位宽规则

RHDL 定义了硬件类型上的运算规则，确保位宽正确。

### 5.6.1 算术运算位宽

```mermaid
flowchart TB
    A[UInt<8> + UInt<8>] --> B{结果位宽}
    B -->|默认| C[UInt<8>（可能溢出）]
    B -->|使用 overflowing_add| D["返回 (UInt<8>, Bool)"]
    B -->|显式扩展| E[UInt<9>]

```

*   默认算术运算结果与操作数同宽，截断高位。
    
*   需要检测溢出时，使用 `overflowing_add` 等返回额外进位。
    
*   显式扩展通过 `extend<W>()` 或 `resize<W>()` 实现。
    

### 5.6.2 逻辑与移位运算

*   按位逻辑：`&`, `|`, `^` 要求操作数位宽相同。
    
*   移位：`<<`, `>>` 移位数可以是常量或信号，结果位宽与左操作数相同。
    
*   比较：`==`, `!=`, `<`, `>` 返回 `Bool`。
    

### 5.6.3 位宽转换

```mermaid
flowchart LR
    A[UInt<8>] -->|"extend<12>()"| B[UInt<12>（零扩展）]
    A -->|"truncate<4>()"| C[UInt<4>（截断低 4 位）]
    A -->|"resize<12>()"| D[UInt<12>（根据符号性扩展/截断）]

```

## 5.7 类型检查与错误处理

RHDL 的类型检查集成在 Rust 编译器中，许多错误在编译期报告。

```mermaid
flowchart TD
    A[代码编译] --> B{位宽匹配?}
    B -- 否 --> C[Error: width mismatch<br>expected UInt<8>, found UInt<16>]
    B -- 是 --> D{方向正确?}
    D -- 否 --> E[Error: direction mismatch<br>cannot connect Output to Input]
    D -- 是 --> F{时钟域绑定?}
    F -- 否 --> G[Error: register not bound to ClockDomain]
    F -- 是 --> H[编译通过]

```

此外，组合逻辑完整性检查也会在类型检查阶段进行，防止锁存器：

```mermaid
flowchart LR
    Comb["#[combinational] block"] --> Assign[输出赋值分析]
    Assign -->|所有路径赋值| OK[OK]
    Assign -->|部分路径未赋值| Error[Error: incomplete assignment<br>latch inference detected]

```

## 5.8 类型系统与可综合性的关系

所有可综合类型必须实现 `HardwareType` trait，该 trait 定义了位宽、默认值、可综合属性等。不可综合类型（如 `Vec<T>` 动态数组）被禁止在硬件描述中使用。

```mermaid
flowchart TB
    subgraph 可综合
        A[Bool, Bits, UInt, SInt]
        B[Clock, Reset]
        C[Bundle, Vec固定, Mem]
        D[Input, Output]
    end
    subgraph "不可综合（编译拒绝）"
        E[String, Vec动态, Box]
        F[Closure, Trait Object]
        G[File, Network]
    end
    A -->|实现 HardwareType| OK[可综合]
    B -->|实现 HardwareType| OK
    C -->|实现 HardwareType| OK
    D -->|实现 HardwareType| OK
    E -.->|未实现| Reject[编译错误]
    F -.->|未实现| Reject
    G -.->|未实现| Reject

```

## 5.9 多视图建模中的类型分离

RHDL 的多视图建模允许功能视图使用普通 Rust 类型，不受硬件类型约束。这种分离确保了综合路径的严格性，同时为功能模拟器提供了软件灵活性。

```mermaid
flowchart TB
    subgraph "周期精确视图（硬件类型）"
        A[UInt<8>, Bool, Reg, Wire]
        A -->|可综合| B[HIR → 硬件]
    end
    subgraph "功能视图（软件类型）"
        C[Vec<u8>, String, 自定义结构体]
        C -->|普通 Rust 编译| D[功能模拟器]
    end
    A -.->|桥接适配器| C
    B -.->|一致性验证| D

```

### 5.9.1 功能视图类型示例

```rust
#[module]
pub struct UartTx {
    // RTL 端口（硬件类型）
    pub clk: Clock,
    pub tx_data: Input<UInt<8>>,
    pub tx_pin: Output<Bool>,

    // 功能模型内部状态（软件类型）
    #[functional_state]
    tx_buffer: std::collections::VecDeque<u8>,
}

```

*   功能视图字段可以使用 `VecDeque<u8>` 等动态数据结构，不会进入 HIR。
    
*   桥接适配器负责在功能视图类型和周期精确视图类型之间转换。
    
*   一致性验证框架确保两种视图在行为上等价。
    

---

RHDL 的类型系统是其安全性和现代性的核心体现。通过将硬件属性编码到类型中，RHDL 让编译器成为硬件设计的第一道防线，大幅减少了位宽错误、方向错误、多驱动冲突和时钟域问题。同时，多视图建模中的类型分离设计，既保证了综合路径的严格性，又为功能模拟器提供了软件开发的灵活性。
