# 2. 设计目标

RHDL 的设计目标旨在解决传统 HDL 在安全性、开发效率和生态互操作性方面的痛点，同时充分利用 Rust 语言的优势。设计目标可归纳为十一个核心方面，它们相互关联、协同作用，共同定义了 RHDL 的独特价值。其中 **多视图建模** 作为新增目标，专门用于降低功能模拟器与周期精确模拟器的生成难度。

## 2.2 强类型安全

RHDL 将类型安全置于核心，所有硬件信号在编译期就具有明确的位宽、方向和时钟域属性，杜绝了传统 HDL 中常见的位宽不匹配、方向错误和跨时钟域冒险。

### 2.2.1 类型层次

```mermaid
classDiagram
    class Signal {
        +width: usize
    }
    class Bool {
        +width = 1
    }
    class Bits~N~ {
        +width = N
    }
    class UInt~N~ {
        +width = N
    }
    class SInt~N~ {
        +width = N
    }
    class Clock
    class Reset
    class Analog

    Signal <|-- Bool
    Signal <|-- Bits
    Signal <|-- UInt
    Signal <|-- SInt
    Signal <|-- Clock
    Signal <|-- Reset
    Signal <|-- Analog

    class Input~T~ {
        +direction = In
    }
    class Output~T~ {
        +direction = Out
    }
    class InOut~T~ {
        +direction = InOut
    }

    Signal o-- Input
    Signal o-- Output
    Signal o-- InOut

```

### 2.2.2 编译期检查流程

```mermaid
flowchart TD
    A[编写 RHDL 代码] --> B[编译 Rust 代码]
    B --> C{位宽检查}
    C -- 不匹配 --> D[编译错误：<br>width mismatch]
    C -- 匹配 --> E{方向检查}
    E -- 错误 --> F[编译错误：<br>direction mismatch]
    E -- 正确 --> G{时钟域检查}
    G -- 跨域未同步 --> H[编译错误：<br>CDC violation]
    G -- 正确 --> I[生成硬件]

```

## 2.3 所有权模型适配硬件

Rust 的所有权系统要求每个值在任意时刻只能有一个可变引用。RHDL 利用这一特性，将硬件信号建模为具有所有权语义的实体，从而在编译期就杜绝了多驱动冲突。

### 2.3.1 单驱动保证

```mermaid
flowchart LR
    subgraph 硬件信号
        signal[reg: Reg<UInt<8>>]
    end

    subgraph 驱动者
        driver1[组合逻辑块 A]
        driver2[组合逻辑块 B]
    end

    driver1 -- "尝试写入" --> signal
    driver2 -- "尝试写入" --> signal

    check{所有权检查}
    signal --> check
    check -- "同一时刻只有一个可变借用" --> pass[编译通过]
    check -- "多个可变借用" --> fail[编译错误：<br>multiple drivers detected]

```

### 2.3.2 借用检查与硬件生成

```mermaid
sequenceDiagram
    participant Dev as 开发者
    participant RustC as Rust 编译器
    participant RHDL as RHDL 过程宏

    Dev->>RHDL: 编写 #[combinational] 块赋值寄存器
    RHDL->>RustC: 展开为 Rust 借用检查代码
    RustC->>RustC: 检查信号的可变借用数量
    RustC-->>RHDL: 通过（单一借用）
    RHDL-->>Dev: 生成硬件（无冲突）
    Note over RustC: 若多个驱动，则编译失败

```

## 2.4 组合/时序逻辑显式分离

RHDL 通过 `#[combinational]` 和 `#[sequential]` 宏显式区分组合逻辑与时序逻辑，避免隐式锁存器的产生，并清晰定义寄存器的更新行为。

### 2.4.1 逻辑分离规则

```mermaid
flowchart TB
    subgraph 组合逻辑块
        C[读取信号<br>计算输出]
        C --> D[写入 Wire 或 Output]
    end

    subgraph 时序逻辑块
        S[读取当前状态<br>计算下一状态]
        S --> T[写入寄存器 d 端]
    end

    Reg[寄存器] -->|q 输出| C
    T -->|d 输入| Reg
    C -->|组合输出| Out[输出端口]

    check{所有输出路径<br>均被赋值?}
    C --> check
    check -- 否 --> latch[编译错误：<br>incomplete assignment<br>可能产生锁存器]
    check -- 是 --> ok[生成组合逻辑]

```

### 2.4.2 时序边界

```mermaid
flowchart LR
    subgraph 时钟边沿触发
        always_ff["always_ff @(posedge clk)"]
        always_ff --> update["执行 #[sequential] 块"]
        update --> reg_d[更新 Reg.d]
    end

    subgraph 组合逻辑持续更新
        always_comb[always_comb]
        always_comb --> compute["执行 #[combinational] 块"]
        compute --> reg_q[读取 Reg.q]
        compute --> wire[驱动 Wire/Output]
    end

```

## 2.7 可综合子集明确

RHDL 明确定义哪些 Rust 特性可被综合为硬件，哪些不可综合。这保证了代码的行为一致性，并使开发者能在编译期发现不支持的抽象。

### 2.7.1 可综合/不可综合边界

```mermaid
mindmap
  root((可综合子集))
    可综合
      基础硬件类型
      if / match
      静态循环
      函数内联
      泛型 / const 泛型
      数组 / 结构体 / 枚举
    不可综合
      动态内存分配
      递归函数
      浮点数（默认）
      动态 trait 对象
      闭包
      文件 I/O / 网络 / 线程
      panic!

```

## 2.8 互转为一级设计目标

RHDL 将与其他 HDL（尤其是 Chisel）的互操作性作为核心设计目标。通过 FIRRTL 中间表示，RHDL 模块可以转换为 Chisel 代码，Chisel 生成的 FIRRTL 也可以导入为 RHDL 模块。

### 2.8.1 互转路径

```mermaid
flowchart LR
    RHDL[RHDL 源码] -->|宏展开| HIR[HIR]
    HIR -->|FIRRTL 后端| FIRRTL[FIRRTL]
    FIRRTL -->|FIRRTL→Chisel 生成器| Chisel[Chisel 源码]
    Chisel -->|Chisel 编译| FIRRTL2[FIRRTL]
    FIRRTL2 -->|FIRRTL→RHDL 导入器| HIR2[HIR]
    HIR2 -->|生成| RHDL2[RHDL 源码]

```

### 2.8.2 互操作层次

```mermaid
flowchart TB
    subgraph 高层次
        A[RHDL 泛型模块]
        B[Chisel 参数化生成器]
    end
    subgraph 中间表示
        C[FIRRTL 模块实例]
    end
    subgraph 低层次
        D[RHDL 生成的低层次模块]
        E[Chisel 生成的低层次模块]
    end
    A --> C
    B --> C
    C --> D
    C --> E

```

## 2.9 支持高层次综合（HLS）

RHDL 计划集成 HLS，允许开发者使用算法级 Rust 函数描述计算，由工具自动生成 RTL（状态机、数据通路、流水线），从而提高设计抽象层次。

### 2.9.1 HLS 流程

```mermaid
flowchart LR
    A["#[hls] 标注的<br>算法级 Rust 函数"] --> B[HLS 前端]
    B --> C[解析数据流图 DFG]
    C --> D[调度<br>分配时钟周期]
    D --> E[资源分配与绑定]
    E --> F[生成 HIR<br>（状态机 + 数据通路）]
    F --> G[与其他 RHDL 模块集成]
    G --> H[Verilog / FIRRTL]

```

### 2.9.2 约束与优化

```mermaid
flowchart TD
    constraints[约束注解] --> hls[HLS 引擎]
    hls --> latency[延迟约束<br>latency=3]
    hls --> pipeline[流水线<br>pipeline=true, ii=1]
    hls --> unroll[循环展开<br>unroll=4]
    pipeline --> opt[生成流水线寄存器]
    latency --> sched[调整调度]
    unroll --> area[面积 / 吞吐权衡]

```

## 2.12 多视图建模与模拟器生成（新增目标）

RHDL 引入多视图建模，允许一个硬件模块同时提供**功能视图**和**周期精确视图**。功能视图使用普通 Rust 代码（事务级/算法级），周期精确视图使用 RHDL 的 RTL 描述。工具链分别生成功能模拟器（快速）和周期精确模拟器（精确），并通过桥接和一致性验证保证两者等价。

### 2.12.1 多视图建模结构

```mermaid
flowchart TB
    subgraph 模块定义
        A[UartTx 模块]
        A --> B["功能视图<br>#[functional_model] 方法"]
        A --> C["周期精确视图<br>#[sequential] + #[combinational]"]
    end
    subgraph 模拟器生成
        B --> D[功能模拟器<br>快速事务级]
        C --> E[周期精确模拟器<br>逐周期 RTL 级]
    end
    D -->|一致性验证| E
    D -->|桥接适配| E

```

### 2.12.2 桥接与一致性验证

```mermaid
flowchart LR
    SW[软件调用] -->|方法调用| TLM[事务级接口]
    TLM -->|转换适配器| RTL[信号级接口]
    RTL -->|时钟驱动| HW[硬件模拟]
    TLM -->|一致性验证| RTL

```

## 2.13 设计目标之间的关联

这些设计目标并非孤立，而是相互支撑、形成闭环：

```mermaid
flowchart LR
    A[强类型安全] --> B[所有权单驱动]
    B --> C[组合/时序分离]
    C --> D[参数化生成]
    D --> E[Rust 生态集成]
    E --> F[可综合子集]
    F --> G[互转 FIRRTL]
    G --> H[HLS 支持]
    H --> I[IP 库]
    I --> J[可视化]
    J --> A
    A --> K[多视图建模]
    K --> E
    K --> H

```

**总结**：RHDL 的设计目标围绕“安全、现代、互操作、高产、多视图”五大支柱展开，通过 Rust 语言的内在优势，为硬件设计提供一个可靠、高效且生态友好的新选择。多视图建模的加入使得 RHDL 能够支持从快速软件开发到严格硬件验证的完整流程。
