**后续执行状态（2026-09-20）：** 用户随后授权依序完成下表全部四项，本轮已完成Chisel真实数值对拍、边界修复/回归、较大流水线CPU与分配剖析和能力清单。见[当前执行证据](backend-boundary-evidence-2026-09-20.md)及[实际剖析](benchmarks/backend-boundary-profile-2026-09-20.md)。下文保留原分析依据与当时建议，不再表示待执行计划。

当前优先级应放在后端数值一致性和可执行验收证据，其次才是性能优化与内部拆分。Phase 23 的历史结项保持有效；FR189 仍未交付，NFR91 不为空。完成规划故事、公开 API 无破坏和真实后端运算正确，是三个不同层面的证据。

## 已有基础

项目已经具备 FrozenHir、解释器与 compiled schedule、独立功能/周期模型生成、Verilog/FIRRTL/Chisel 输出及多种外部门禁。当前维护批次增加独立位向量参考、真实生成 crate 编译、直接 Verilog 与 firtool 降级 RTL 对拍、三库 SemVer 检查和 release 性能基线。详见[维护记录](simulator-reliability-maintenance.md)和[基线报告](benchmarks/simulator-baseline-2026-09-20.md)。

这些证据覆盖特定设计和输入，不能由测试总数推导所有 HIR、所有后端均已等价。尤其 SemVer 工具检查公开 API 结构，不能证明输出数值或生成代码行为不变。

## 建议执行顺序

| 顺序 | 工作 | 代码依据与原因 | 完成标准 |
|---|---|---|---|
| 1 | 修正 Chisel 有符号逻辑右移，并纳入现有数值矩阵 | `crates/rhdl-firrtl/src/chisel.rs` 中 `Shr` 与 `Sar` 均直接使用 `>>`；对 SInt，逻辑与算术语义不能如此合并。独立审阅已登记该既有问题。 | 生成 Scala 实际编译、降为 RTL 后运行同一独立参考矩阵；SInt8 的 0xff 逻辑右移一位得到 0x7f，算术右移仍为 0xff；覆盖异宽输入/目标及大移位。 |
| 2 | 扩大差分回归，明确仿真与后端支持边界 | 当前主要矩阵是确定性算术设计。`PortValues` 存储 u64；Sim 调度使用首模块；FIRRTL 存储器写目前仍以注释形式输出。不能把这些路径视作任意位宽、任意层级、完整存储器硬件语义。 | 针对正式承诺的子集加入固定种子生成设计、组合依赖顺序、寄存器反馈、同址读写和多模块测试；未承诺能力写明限制，新增产品能力另立验收合同。对失败保留最小设计、输入和工具版本。 |
| 3 | 做真实工作量剖析，再决定性能改动 | 当前基线涵盖计数器、16 个算术操作和固定地址存储器；存储器选择 compiled 仍回退解释器。`tick` 中有模块/调度克隆及字符串映射访问，尚未证明它们是主导热点。 | 增加 RV32 或较大流水线样例；采集分配与 CPU profile，交替测量两种引擎，保留校验和及多次样本。只优化实测热点，并通过数值矩阵；单纯文件拆分不算性能收益。 |
| 4 | 建立按能力索引的验证清单 | 独立 JVM、CIRCT、formal、SystemC 门禁与 `cargo test --workspace` 不完全等价；发布预演也不等于已发布。 | 每项能力列出入口命令、固定工具版本、最近执行结果、是否真实运行外部工具和剩余限制；发布前按实际变更选取门禁，避免用文本存在性测试替代编译与执行。 |

## 如何推进

当时建议下一批只选第一项（后续用户已改为全部四项并完成），作为一个可独立审阅的维护故事，用 `bmad-build` 执行，按“一故事一提交”保留变更与证据。第二项可逐个子集扩展，不必先重构全部仿真器。若扩展到尚未承诺的多模块仿真、完整 FIRRTL 存储器路径或任意精度计算，应先用 `bmad-correct-course` 明确范围与验收，不把既有结项自动解释为新增授权。

暂不建议为了版本号、关闭账本或拆分大文件而升级 firtool、重开大阶段或进行广泛重构。先把真实差分测试建立起来，才能可靠评估这些改动的收益与风险。
