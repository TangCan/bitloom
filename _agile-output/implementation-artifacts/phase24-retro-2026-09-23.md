## 主要发现与经验

1. **缓存路径不应仅检查末级目录。** 当前`external_ip.rs:1462–1472`只对source根目录做symlink_metadata，未拒绝祖先链接。将副本的`cache/closures`指向缓存外，当前CLI `external-ip verify --offline`仍退出0，sources=3。命令、当前二进制SHA和路径见[实测反例](../test-artifacts/phase24-retrospective/symlink-probe.json)。原缓存未改，无联网。
2. **回滚必须区分已有资源与本次创建资源。** `publish_closure_cache`在已有闭包时复用它，但`lock`在许可证发布失败时无条件删除闭包（`external_ip.rs:1375–1379`）。父代理逐段核实；本次未联网重跑完整lock，不把代码推导写成实测。
3. **历史事实和当前说明需要分开。** `docs/ip/csr.md:3`与`module-composition.md:32`仍直接宣称M2/M1未完成；索引的历史说明无法覆盖从外部直接进入页面的读者。修正文档时也应链接本轮维护缺口，不能仅贴“全部完成”。
4. **系统入口与验收链值得单独验证。** 当前真实两拓扑Icarus/vvp运行通过（3 passed / 0 failed / 3 ignored）；三项ignored是本轮未跑的专用后端/formal门。独立示例commit `b3a5621`完成8场景教程演练，并发现和修复runner清理问题。这是可复现操作证据，不是真人学习反馈，也不能把示例中的bug归给rhdl。
5. **把跨故事验证提前到故事关闭之前。** 原补审已修复direct-CSR后端覆盖、reset/提交属性与原始证据保留遗漏（phase24-closeout-review.md）；本轮verification-gap在检查切片无新增确证发现。保留这些已修门禁，不重复制造“尚未修复”事项。

架构聚合检查未发现设计crate依赖CLI或第二HIR。CSR生产端口枚举有重复，external_ip.rs为2261行并承担多项职责；这些是维护观察，不凭行数或假设扩展场景要求立即重构。完整12项候选及裁定见[审查记录](../test-artifacts/phase24-retrospective/review-findings.json)，[检查范围](../test-artifacts/phase24-retrospective/review-scope.md)明确列出未覆盖项。
