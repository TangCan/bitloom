### 现状（实现前必读）

**已可用（勿重复发明）：**

- `ElaborateSession::declare_reg` + `assign_reg_d_from`：同步复位 Reg（AD-15）；`rv32_core` 的 `pc`/`x1`… 即此模式。
- `assign_mux` / `assign_eq` / `assign_lit`：组合选择进 HIR/`tick`（15.1 已补）；`begin_then`/`else` **仍只做 latch 分析，不进入可仿真分支**。
- `declare_sync_read_mem` + `assign_reg_d_mem_read`：15.1 已证明；**取指用不用片上 IMEM 由 17.2 钉死**，本故事不强制重证，但决议可引用 15.1。
- `assign_mem_write_en`：顺序 `we` 门控已存在（15.3）；勿再写「无 we」旧债。

**已知陷阱（防回归）：**

1. **Stall 勿用模块级 `en`：** `declare_reg_ex(..., has_enable: true)` + 端口名 `en` 是 AD-23 全模块 clock-enable（sim 对名为 `en` 的输入采样）。流水 stall 需要**按级**冻结 PC/IF-ID、同时让其他级前进 → 应用 **mux hold**（`assign_mux` + `assign_reg_d_from`），或另开语言故事做 per-reg enable。本闸门若证 hold mux 即可，**不要**把「整核 `en=0`」当成 load-use 方案。
2. **无 Bundle/Vec（AD-20）：** 级间字段用扁平 `declare_reg`/`declare_wire`，禁止发明打包类型走可综合路径。
3. **设计 crate 不得依赖 `bitloom-hir` / CLI / 后端作 `[dependencies]`**（AD-6 / NFR29）。
4. **勿改 `rv32_core` 为流水：** 17.3 仍单周期/边沿提交冻结 imm；17.4 才插五级。本故事只写独立 spike。

### Architecture compliance（必须遵守）

- **AD-1：** 证明路径 = `elaborate()` → `FrozenHir` → `tick`；禁止 rustc 编译期旁路网表。
- **AD-5：** 周期精确只走原生 `tick`；可选 emit `.v` smoke。
- **AD-6 / AD-2：** 设计 → `bitloom-prelude` only；公开品牌 Bitloom。
- **AD-7 / AD-12：** 不新增平行 HIR；不把 flatten 当第二种公开 Hir。
- **AD-15：** 单时钟 + 同步高有效 Reset；`tick` = 一个 posedge。
- **AD-21：** 若触及 Mem/SyncReadMem，用友好表面名；互转合同仍是规范 `mem`。
- **MSRV：** rustc **1.97.1** / edition **2024**（NFR28）。

### 建议证明物形状（非强制 API 名）

最小可接受：

- 级 A Reg `s0`、级 B Reg `s1`：每拍 `s1 <= s0`，`s0 <= in`（两级流水寄存器）。
- 组合 `fwd = mux(fwd_sel, s1, bypass_in)`（或 `mux(fwd_sel, producer, consumer_operand)`），黄金：`fwd_sel=1` 时输出等于旁路源，而非陈旧 `s1` 消费者路径。
- 文档一行：映射到 Harris「EX/MEM→EX」教学语义即可，**不要求**五级命名齐全。
