## Intent

**Problem:** Designers could confuse capturing Wire/Reg hardware refs with legal elaborate-time generator closures; FR73 paths lacked a clear diagnostic for illegal capture (NFR35 / AD-18).

**Approach:** Documented Option C — `HwCaptureRef` (Wire/Reg/Signal markers) + `ElaborateSession::assert_no_hw_capture` / `reject_hw_capture` → stable **`rhdl::E0142`**. FR16 cycle-accurate capturing-closure path stays **`rhdl::E0141`** via `reject_unsynthesizable`. Docs distinguish non-capturing elaborate-time vs capturing.

## Boundaries & Constraints

**Always:** FR73/NFR35/AD-18 diagnostic failure (not silent success); FR16 E0141 regression red; Bitloom / `bitloom-prelude`; keep 27.1/27.2 green.

**Never:** silent success on documented illegal capture; reclassify FR16 as E0142; store closures in FrozenHir; comb/seq inlined closures (Epic 28).

## I/O & Edge-Case Matrix

| Scenario | Expected |
|----------|----------|
| `assert_no_hw_capture(&[HwCaptureRef::wire("w")])` + finish | `rhdl::E0142` |
| Reg capture during factory | `rhdl::E0142` |
| Empty `assert_no_hw_capture(&[])` + mem init | success (27.1 green) |
| `reject_unsynthesizable("capturing closure")` | `rhdl::E0141` (FR16) |
