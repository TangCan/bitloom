# Story 130.2: 来源清单、锁定与离线重放

Status: done

## Story

作为实现/集成维护者，
我希望为一个固定版本的小型外部 RTL 候选建立可执行的来源 manifest、不可变 lock、许可证归档和禁网重放，
以便 FR199 能由真实源闭包和失败关闭的证据验证，而不是依赖浮动引用、工作区外缓存或一次性联网成功。

估算：2–3 有效人日。Richard 负责长期维护、许可证与再分发决策，Codex 负责本次实现和证据，主代理负责七步流程与单 Story 提交；估算不是代理墙钟时间或发布日期。

## Acceptance Criteria

1. **前置与范围。Given** Story130.1 已 done、Epic126–129 已关闭且 Epic130 in-progress，**When** 实施本 Story，**Then** 只交付 FR199 来源治理与离线重放；130.3 保持 backlog，FR200、真实 Bitloom wrapper 行为、`compiled`/`behavior-tested`/`maintained`、Epic130 和整个 Phase24 均不关闭。FR189/Epic122 deferred、NFR91、既有 done、产品工具 pin 和发布状态保持，不 push、不 publish。
2. **Manifest 与 lock 分责。Given** AD-31/NFR98 和 `epic-130-nfr14.md`，**When** 定义机器可读来源描述，**Then** manifest 记录依赖意图与维护合同，lock 记录一次解析后的不可变身份；两者有版本化 schema、确定性序列化和 fail-closed 校验。必须记录 upstream URL、来源类型、`v1.40.0` 意图、tag 类型/object、peeled/full commit、全部递归依赖 full commit、ordered filelist、include、宏、编译顺序、生成器输入/版本、每个源码与归档 SHA256、缓存布局、顶层 module、参数、端口宽向、clock/reset、wrapper 版本/owner、证据路径、最后通过 UTC、升级/弃用策略。不得把 URL/tag 名或单一 archive hash 当完整 lock。
3. **Stable 候选身份。Given** 首选候选为 PULP `common_cells` stable `v1.40.0` FIFO，**When** 从上游重新解析，**Then** 核验该 lightweight tag 当前直接指向 full commit `1281545696eb3fcba50ec5b4275993476a3c710e`，stable 文件为 `src/fifo_v3.sv`、module `fifo_v3`；实际参数/端口/include 必须从锁定内容提取并与 manifest 对照。`Bender.yml` 声明的 `common_verification 0.2.0`、`tech_cells_generic 0.2.11` 及其递归依赖必须按所选 target 的真实闭包解析，不能因试点只消费 FIFO 就静默遗漏；若合法 target 可证明依赖不参与闭包，须保存工具输出和理由。master `cc_fifo` 证据不得替代 stable，候选不合格时记录拒绝并停止，不自动切 Taxi 或浮动 master。
4. **许可证与再分发材料。Given** 主仓库 stable `LICENSE` 是 Solderpad Hardware License v0.51 文本，**When** 固化闭包，**Then** 对主仓库和每个实际递归依赖归档精确许可证原文路径、内容 SHA256、NOTICE 存在/缺失事实、copyright/attribution 与再分发义务，并记录 Richard 的审阅责任。不得由主仓库许可证外推依赖许可证，不得把“无 NOTICE 文件”写成“无 NOTICE 义务”；任一材料未知或漂移即非零失败且 FR199 不交付。
5. **两阶段获取与禁网重放。Given** 声明的 manifest，**When** 执行验收，**Then** 阶段 A 在真实空缓存中允许联网，解析并获取声明的完整闭包、生成 lock 和内容寻址缓存；阶段 B 使用隔离 checkout 与仅含阶段 A 产物的独立缓存，通过实际网络隔离重新校验、生成并至少完成锁定 filelist 的真实 HDL parse/compile。两阶段保存命令、UTC、耗时、退出码、工具路径/版本/hash、源身份和原始日志；阶段 B 不读取主工作区 target、用户 HOME 缓存、联网 DNS/HTTP/Git 或未声明路径。网络 fetch 成功和 `bwrap` 存在本身都不算重放 PASS。
6. **失败关闭与负测。Given** 可复制的临时 manifest/lock/cache，**When** 分别注入浮动 ref、tag/commit 不一致、源码/hash/license/NOTICE 漂移、缺失递归依赖、漏列/新增源码、乱序 filelist、缺失 include/宏/生成器输入、缓存外读取、网络访问和工具身份漂移，**Then** 每类在普通与优化执行模式下均确定性非零失败并给出可定位诊断，且不得修改真实 lock、缓存或 sprint。禁止 skip、自动重锁、自动换源、回退联网、读取宿主缓存或仅告警继续。
7. **架构和产品边界。Given** 获取/解析属于 CLI/构建层且设计 crate 只依赖 `bitloom-prelude`，**When** 选择最小实现，**Then** 优先复用现有 Git/Bender/FuseSoC 能力及 `firtool.rs`/CIRCT 脚本的 cache/hash/fail-closed 模式，不重写通用包管理器；第三方源码不进入 HIR，prelude 不联网，设计 crate 不依赖 CLI。若新增 CLI 表面或公开 schema，须有解析/错误/API兼容测试并按 FR142/SemVer 规则登记；若脚本和私有 schema 足以完成 FR199，不为 130.3 预造公共 wrapper API。
8. **诚实验证与关闭。Given** 本 Story 不交付 FR200，**When** 完成 ATDD、build、独立 code-review、automate、实际 `cargo clean && cargo fmt --all && just test` 和单 Story commit，**Then** 只有在 manifest/lock/license/两阶段 replay 与全部 P0 负测实际通过后将 130.2 标 done。支持矩阵最多记录可证实的 `catalogued`/`locked` 来源事实，不得提前写 `compiled`、`behavior-tested` 或 `maintained`；130.3 仍须完成真实 binding、上游测试和独立 Bitloom RTL 行为。

### Replay And Evidence Rules

- 在线和离线阶段必须使用不同的空目录与显式环境。离线阶段建议用 `bwrap --unshare-net`，同时清空/重定向 `HOME`、XDG、Git、Cargo 及工具缓存；必须主动探测网络不可达和宿主缓存不可见，而不是只看命令行参数。
- cache key 至少绑定 schema、upstream URL、full commit、递归依赖身份和内容 hash。解包须拒绝绝对路径、`..`、symlink/hardlink 越界及非预期文件；原子写入后再发布 cache entry，失败不留可误用的半成品。
- 锁验证要区分 manifest 意图漂移、lock 身份漂移、内容漂移和工具漂移。默认运行不得自动更新 lock；显式生成与验证命令必须分开。
- 所有正向证据保存 exact command、环境白名单、源起止 Git SHA、输入/输出 manifest、工具身份、退出码和日志。负测使用副本并校验真实 manifest/lock/cache/sprint 的字节或 SHA256 未变。
- 若实际依赖解析表明 `fifo_v3` 的所选 compile target 不需要某个 Bender dependency，证据必须包含解析器输出、target 条件和真实 compile；不得仅因源码表面未 import 就删除依赖。
