## Intent

**Problem:** HLS authors cannot express dataflow transforms with closures that dissolve before external schedule/lower; FR76 / Cap-R-62/71 require D1 HLS-free path without leaving Fn in artifacts or inventing an in-tree scheduler.

**Approach:** Minimal emit-prep API mirroring CombInline: `dissolve_dataflow_transform(..., || HlsDataflowOp::…)` checks D1 constraint tokens, expands to C, then `run_hls_dissolved` / CLI `--dataflow` call pinned Bambu (or emit-only / bambu-ci-stub). No in-crate scheduling (AD-25).

## Boundaries & Constraints

**Always:** FR76 dissolve-before-schedule; D1 HlsFree only on AD-25 external HLS; NFR36 no closure residue; missing backend readable failure; Bitloom brand; reuse FR35/FR50 product path.

**Ask First:** Expanding HlsDataflowOp beyond unary/binary aliases; attaching dissolve into rustc proc-macro body analysis.

**Never:** In-tree HLS scheduler (AD-25 / FR86); silent skip success when backend missing; smuggling HlsFree onto synthesizable comb/seq (use SynthesizableClosure); store Fn in C/RTL/HIR.

## I/O & Edge-Case Matrix

| Scenario | Expected |
|----------|----------|
| `dissolve` + empty violations → XorConst | C has `x ^ Ku`; no Fn/closure tokens |
| violations non-empty | readable reject before emit |
| emit-only | `.c` only; not counted as RTL success |
| bambu-ci-stub path | synthesizable `.v` under out-dir |
| missing bambu | non-zero + install/`BITLOOM_BAMBU_PATH` message |
| CLI `--dataflow xor_a5` | same dissolve path as library |
