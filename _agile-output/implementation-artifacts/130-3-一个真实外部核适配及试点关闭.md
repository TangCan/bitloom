# Story 130.3: 一个真实外部核适配及试点关闭

Status: done

## Story

作为实现/集成维护者，我希望将锁定的 PULP stable fifo_v3 接入 Bitloom 现有模块组合和真实 RTL 验证，以交付 FR200 与 FR201 外部试点，而不是仅列出来源或通过一次编译。

前置：130.2 的 FR199 验收、126.2 模块组合、130.1 NFR14。130.2 已由独立来源快照验收并提交（4152610），前置已满足。

## Acceptance Criteria

1. Given 固定 v1.40.0、完整 source lock 和许可证，When 生成 wrapper，Then 真实模块/源码/参数/端口/clock/reset 必须逐项对应；JSON 不是可执行绑定的替代物。
2. Given 同一 session 的外部端口声明及组合父模块，When Bitloom 生成 RTL 并链接锁定源码，Then 测试消费 Bitloom 发射的实际父模块；源不嵌入 HIR，无第二 IR，无原生零输出模型。
3. Given NFR14 单一冻结参数集 32-bit/depth8/fall-through0，When 测试，Then 核验上游默认值及独立模型下空/满、拒绝读写、同拍读写、数据顺序、有数据时异步复位、flush 与复位释放；不声称未测参数集。
4. Given 原始上游测试和独立组合 RTL oracle，When 验收，Then 两者均真实运行，有非零检查数量、固定 seed、原始日志和全部工具身份；upstream test 不替代独立 oracle。
5. Given 清缓存取得的复制产物，When 禁网重放，Then 原始 checkout/cache 不可读、缓存只读、scratch 独立，实际 binding/compile/sim 成功；记录命令/UTC/hash/超时/退出码。
6. Given P0 来源、hash、依赖、端口、参数、reset、工具、网络、未声明文件及空壳负测，When 普通及优化 Python 运行，Then 先证明正向基线，再证明预期类别失败，canonical 产物不变。
7. Given build、独立 code-review、automate 与 clean/fmt/just test 全部实跑通过，When 单故事提交，Then 才可关闭 130.3/Epic130；FR189/NFR91 与全部既有关闭保持，未运行或 ignored 不计 PASS。支持矩阵在此之前保持未交付。
