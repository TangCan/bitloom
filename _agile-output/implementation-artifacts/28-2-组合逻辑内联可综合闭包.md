## Intent

**Problem:** Designers cannot reuse pure transforms inside `#[combinational]` without hand-duplicating expressions; FR75 Cap-R-55 requires elaborate-time inline of SynthesizableClosure-constrained closures into ordinary HIR.

**Approach:** Minimal MVP on `ElaborateSession`: `inline_comb_fn(dst, args, violations, span, |args| CombInline::…)` (plus marker helper). Cap-R-60 check from 28.1 runs first; legal closures expand once into existing `assign_*` / Wire assigns. FrozenHir never stores `Fn` (NFR36). Incomplete-assign latch rules unchanged (AD-18).

## Boundaries & Constraints

**Always:** FR75 comb path (Cap-R-55); call/respect SynthesizableClosure check (28.1); NFR36 no closure residue; AD-18 incomplete-assign; Bitloom / `bitloom-prelude` design surface.

**Never:** sequential inline (→ 28.3); store Fn / closure IR in FrozenHir / backends; silent skip of Cap-R-60 violations; new HIR closure nodes.

## I/O & Edge-Case Matrix

| Scenario | Expected |
|----------|----------|
| `inline_comb_fn` + empty violations → mux/add | ordinary AssignExpr; emit `.v` + tick match handwritten golden |
| violations non-empty | Cap-R-60 diag (E0143–E0145); no expand; finish fails |
| Freeze after legal inline | no Closure stmt/expr / Fn residue (NFR36) |
| Incomplete if/else with inline dest | still `rhdl::E0110` latch (AD-18) |
| Design crate deps | only `bitloom-prelude` |

</frozen-after-approval>

## Story

As a 设计者,
I want 在 `#[combinational]` 中调用满足约束的闭包并得到组合逻辑,
So that 可复用纯变换而不手写重复表达式。

4. Existing incomplete-assign comb rules still apply (AD-18)
