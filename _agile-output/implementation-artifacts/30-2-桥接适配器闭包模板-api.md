## Intent

**Problem:** 验证/桥接作者缺少可复用的事务↔周期握手模板（`start_wait_complete`），手写「启动→等 busy 清」样板易把功能侧闭包误带进周期精确/`tick`。

**Approach:** 在 **`bitloom-prelude`** 交付 host/桥接侧模板 API（trait 默认方法 + 自由函数等价）：`start_fn` 仅在 host 路径自由设置信号级字段；模板循环只调用 `tick`/`is_busy`。周期精确侧始终只见普通信号/`PortValues`（NFR36）。文档钉死 Cap-R-66/67 视图边界。不实现 FR47 联验（→ 30.3）。

## Boundaries & Constraints

**Always:** FR78 / Cap-R-65；NFR36（周期侧无闭包对象）；功能侧可自由闭包（Cap-R-66/67）且文档标明边界；依赖 Story 30.1 + Epic 27；AD-5 不以 SystemC TLM 为合同；设计 crate 只依赖 `bitloom-prelude`。

**Ask First:** 无。

**Never:** 把模板闭包写入 FrozenHir / FIRRTL / Chisel / `Sim::tick` 参数；冒充 FR73/FR75 硬件闭包；用 FR47 sim generators 冒充 FR78；SystemC TLM；FR47 联验与 Epic 30 关闭勾选（→ 30.3/30.4）。

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Trait `start_wait_complete` | host 实现 `is_busy`/`tick`；`start_fn` 置 start | 先执行 start，再 tick 直至 not busy | busy 永不结束 → 测试超时/夹具保证有限 busy |
| Free-fn 等价 | 传入 `tick`/`is_busy` 闭包 + start | 同 trait 语义 | 同上 |
| 驱动 cycle-accurate DUT | 模板展开后仅 `PortValues` 进 `Sim::tick` | 握手完成；无 Fn 进 HIR | NFR36 抽检源/文档 |
| 功能侧自由闭包 | host/functional 用 Rust 闭包发事务 | 合法；文档标明不进 tick | 文档/ATDD 边界断言 |
| 误用为可综合闭包 | 文档/决策表消歧 | 明确 ≠ FR74/FR75 | 文档禁止事项 |

## Dev Notes

- **落点决策：** API 在 **prelude**（设计 crate 可依赖）；语义是 **host/桥接** 模板，不是 elaborate-time 生成器（≠ FR73）也不是 SynthesizableClosure（≠ FR74/75）。
- **NFR36：** 闭包只存在于 host 调用栈；对 DUT 只写端口/`PortValues` 再 `tick`。
- **Epic 27：** 本故事不调用生成器 API，但合同依赖「冻前消解」通路已存在；桥接模板本身不进 HIR。
- **AD-5：** 无 SystemC TLM；对照仍是 PortValues。
- 品牌 Bitloom；公开表面经 `bitloom-prelude`。
- **文档等价：** 默认方法为 `start_fn` → **一次 commit tick** → `while is_busy { tick }`，以便寄存器 busy 能在等待环前拉高。
