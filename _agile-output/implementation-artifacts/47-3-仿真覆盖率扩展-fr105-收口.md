## Dev Notes

### Decision — Mux branch coverage (C2) + explicit C3 crop

Instrument `AssignExpr::Mux` evaluation: for each `sel` name, record whether the true arm and/or false arm was taken across ticks (`branch_hit mux:<sel>:t` / `branch_miss mux:<sel>:f` style, or equivalent stable tokens). Keep FR34 toggle sampling unchanged (C1).

**C3 FSM:** MVP **explicitly crops** full state-enum visit coverage in `docs/fr105-sim-coverage-ext.md` (NFR14 allows this if declared). Do not silently omit.

**Report dialect:** Prefer `# bitloom-sim coverage v2` extending the line-oriented text so existing `hit`/`miss` lines remain; add `branch_hit` / `branch_miss`. Keep `parse_report` working for toggle; add `parse_extended_report` or extend return type. Fixture must demonstrate ≥1 toggle hit, ≥1 toggle miss, ≥1 branch hit, ≥1 branch miss (or document if a minimal Mux fixture only guarantees branch pair + toggle pair across the same run).

### Architecture

- Lives in **`bitloom-sim`** (toolchain). Design crates stay **`bitloom-prelude` only** (AD-6).
- `eval` today is `&self` — change to `&mut self` (or `RefCell` on Coverage) so Mux can record without redesigning the public Sim API surface beyond `coverage_report()`.
- Do **not** remove FR34 `# bitloom-sim coverage v1` semantics for toggle; v2 may supersede the header while retaining `hit`/`miss` lines (update fr34 doc if header bumps).
- FR104 `interactive.html` path untouched except doc status pointers.
