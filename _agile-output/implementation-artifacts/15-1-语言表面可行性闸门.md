# Story 15.1: 语言表面可行性闸门

Status: done

## Story

As a 实现者,
I want 在写完整 RV32 核之前证明 Bitloom 表面能表达 Episode I 所需控制与存储端口,
So that 不会在实现中途才发现语言缺口。

## Acceptance Criteria

见 `epics.md` Story 15.1（FR60 / NFR24）。

## Tasks / Subtasks

- [x] 记录缺口：`begin_then`/`else` 仅为 latch 分析，原先无数据相关 Mux/Eq/Lit 赋值进 HIR/`tick`
- [x] 补齐最小语言表面：`AssignExpr::{Eq,Mux}` + builder `assign_lit` / `assign_eq` / `assign_mux`；sim/vlog/firrtl/chisel
- [x] `examples/rv32_feasibility` spike：多状态控制 + SyncReadMem + 同步复位；`elaborate` + `tick` 黄金
- [x] 书面决议见 `examples/rv32_feasibility/FEASIBILITY.md`
- [x] ATDD / automate / regression / code-review / commit

## Dev Notes

- 设计依赖仅 `bitloom-prelude`；`bitloom-sim` 仅 dev-dep。
- 微架构决议：Episode I 采用**单周期或显式 FSM**均可；数据相关选择走 `assign_mux`/`assign_eq`，不要依赖 `begin_then` 产生 HIR 条件。
- 顺序过程内按 `we` 门控写 mem 仍缺口：测试保持幂等写；完整核可在 15.2/15.3 用 mux 到地址/数据或后续 seq-if 故事。
