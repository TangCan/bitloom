# Phase 24 变更提案：可组合 IP 与可验证生态

建议把下一阶段重点转到可组合 IP：先修复既有 AXI 接口，再交付 CSR 总线和 UART/GPIO/Timer/IRQ 系统；外部开源 IP 以一个可复现的小核试点单独验收。本文及附件为待批准提案，未改正式合同，未启动实现。

## 1. 问题与证据

触发是用户提出“性能收益不明显时，继续增加内置 IP 与现成开源 IP 库”，并批准开展深入研究。这是新增产品方向，当前没有需要回滚的在制故事。研究和实现计划完成后，用户要求继续整理正式范围。

- [研究报告](research/technical-bitloom-composable-ip-ecosystem-2026-09-20/research.md)覆盖 26 个来源；[实现计划](research/technical-bitloom-composable-ip-ecosystem-2026-09-20/implementation-plan.md)提供接口合同、17 个工作包、验证与维护方案。
- 本地 native 探针在基线 29c52df 观察到：AW 与 W 分拍被接受却未返回 B；AW/W 与 AR 同拍被接受时读请求丢失。见 [源码/探针记录](research/technical-bitloom-composable-ip-ecosystem-2026-09-20/imports/project-audit.md)及同目录 axi-observation.rs/log。探针证明指定输入下的缺陷，尚未执行真实 RTL 复现；观察缺陷的测试通过不等于协议测试通过。
- 当前 AXI 接收与内部提交条件不一致；允许同时等待 AWVALID/WVALID 再一起握手本身不是协议错误，接受后遗失请求才是要修复的问题。
- 已有 IP 单体和 blackbox 入口不等于可组合系统或第三方核已适配。native/generated 层级限制、FIRRTL 内存缺口必须在首版边界中体现。
- 性能测试尚未给出稳定 compiled 加速；这支持重新排序工作，但不证明新增 IP 必然提高采用率。生态收益仍需实测。

## 2. 影响分析

**历史范围：** 全文件编号/状态扫描确认 FR 最大 191、NFR 最大 92；Epic 1–124 中 123 个 done、122 为 deferred。关联 Epic 22/34/43/45/50/61/75/78/101 的 IP、双模型、pad 和布局结论保留，新增缺陷另立回归和修复证据。不能因历史关闭而掩盖缺陷，也不把新范围倒写为历史 AC。Phase 23 诚实结项、FR189 未交付与 NFR91 仍有效。

**产品文档：** PRD/addendum、canonical SPEC、epics 追加新合同；原 FR48 五类 smoke 保留。现有用户旅程增加完整外设组合例子。没有独立 GUI 设计变更。

**架构与代码：** 主要触及 prelude 的 ip/模块构建 helper、AXI 手写功能模型、CLI 构建产物关联、测试与文档。保持唯一 FrozenHir、现有 Diagnostics 与 AD-6 依赖边界。新增 AD-30/31 候选决定见附件；不调整 MSRV、firtool/Chisel 钉或模拟器公共接口。

**API：** 旧入口兼容，新增候选表面包括模块定义 helper、RvRegSlice、ParamSyncFifo、CSR 描述/桥/译码、Timer/IRQ/GPIO/UART wrapper。名称与逐符号稳定表面在 125.1 明确，不能靠本提案静默扩大 FR142；每个实现故事执行适用兼容检查。

**基础设施：** 固定 BFM、仿真、综合与形式工具；独立通道驱动、原始特殊事务、参考模型、失败种子/波形。严格 job 缺工具应失败，不能以 skipped 冒充通过。外部依赖需完整源码闭包和禁网重放。发布/远程同步不在本次执行窗口。

## 3. 方案选择与成本

| 方案 | 评价 | 决定 |
|---|---|---|
| 在既有计划后追加独立阶段 | 保留历史结项，可先解决协议基础，再复用组件；能分别衡量核心与外部成本 | 推荐 |
| 回滚已完成后端或 IP 工作 | 没有证据说明回滚会改善组合能力；将丢失已验证功能 | 不采用 |
| 缩减为继续增加零散 IP 名称 | 交付快，但不能验证系统组合和生态维护价值 | 不作为本阶段目标 |
| 首版直接集成大型 Ethernet/DDR/PCIe | 许可证、源闭包、验证和板级成本尚未定界 | 留待用户场景驱动 |

建议执行顺序：M0 协议基础 → M1 组合/流基础 → M2 CSR/桥 → M3 外设 → M4 系统。M3 可按故事依赖提前开展；M5 外部试点在 M0 后与核心交错安排，真实适配依赖模块组合。此处描述依赖并行性，不意味着已分配多人。

|---|---:|---:|---:|---:|
| M0 合同与 AXI | 125 | 3 | 5–8 | 已包含 |
| M1 组合/流/FIFO | 126 | 4 | 8–12 | 0.5–1 |

原功能工作包 46–72 人日；新增 5 个独立 NFR14 故事计 2.5–5 人日，合计 **48.5–77（约 49–77）人日**。一名熟悉项目的工程师每周 5 个有效工作日，约 10–16 周；再预留 25% 约 61–97 人日、13–20 周。核心约 43–68 人日，外部约 5.5–9。估算包含各功能测试评审，不是进度承诺；人员可用性、实际工具兼容性和缺陷修复会影响日历时间。M0 结束后必须重估。

主要风险及措施：

1. **协议缺陷影响扩展。** 先用真实 RTL 红测验证，再修旧 AXI 与 FL；旧问题未闭环，不启动新桥。
2. **组合 API 与当前模块生命周期冲突。** 共用 session、一次 freeze，先验证重复参数实例和局部重名；不合并冻结 HIR。
3. **CSR 副作用重复。** 唯一 req handshake 提交点，响应锁存；W1C 同拍硬件 set 优先，错误访问无副作用。
4. **层级/内存后端缺口。** 首版用小寄存器 FIFO；层级走真实 RTL，不把 native unsupported 隐藏为成功。
5. **外部候选不适配。** PULP 稳定版 tag/source/闭包仍待核验；失败就保留未交付，不让目录项冒充可用核，不阻塞核心结项。
6. **维护负担超过复用价值。** 两个组合例子、维护人、CI 成本与升级成本作为扩库依据；无维护人或无法复现则不进入 maintained。

## 4. 具体变更

[详细变更文本](phase24-composable-ip-proposal/change-set.md)提供逐文件 OLD→NEW、FR192–201/NFR93–99、22 个故事与 AC、AD-30/31、状态登记和文档改动；[机器可读故事清单](phase24-composable-ip-proposal/stories.json)记录依赖。所有编号均为候选，批准落地前再检查占用。

首版语义采用研究计划 §3：单时钟、32-bit 数据/16-bit 地址；UART/GPIO/Timer/IRQ 四个 0x100 窗口；独立 AW/W/AR 捕获及轮转仲裁；最多一个 CSR 执行中请求；B/R 背压保持；RW/RO/W1C/WSTRB/错误行为明确。首版不包含 DMA、PWM、watchdog、SPI/I2C 加深、深 RAM FIFO、原生层级仿真和复杂外部核。

验收必须分别保存 direct RTL、Chisel/JVM→RTL、受支持 FIRRTL→RTL、Rust、综合、形式属性的实际结果。BFM 高层操作不能替代特殊 WSTRB/原始地址/半笔事务 reset；活性属性写明公平性假设。系统复位要求板级同步断言与释放；输入同步链不证明物理 CDC 或板级电气可靠性。
