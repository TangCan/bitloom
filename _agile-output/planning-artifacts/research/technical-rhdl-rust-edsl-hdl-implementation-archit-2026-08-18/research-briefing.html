technical research：RHDL Rust eDSL 实现架构

类型 technical 预设 deep · 校验 normal 日期 2026-08-18 声明 verified 3 / unverified 8

决策：把 Rust 嵌入式 RTL HDL（过程宏→HIR→Verilog/FIRRTL，含 Chisel 互转与多视图）落到 2026 年可执行实现方案。

摘要 建议 维度 未决 来源 过期图

执行摘要

现在该做的事：按 Chisel 式分阶段展开 + 自有 HIR；阶段一直接出可综合 Verilog；阶段二再出 FIRRTL 6.0 子集并钉死 firtool-1.155.0。与 Chisel 改为单向导出 + 有损导入。多视图用两套模型。不要在 crates.io 发布名 rhdl。verified

  • Chisel 7.14.0 → firtool-1.155.0；不能把 .fir 解析回 Circuit（#4899）。
  • samitbasu/rhdl 走 RHIF→Verilog，无 FIRRTL；crates.io rhdl 0.1.0 是 3 行占位包。
  • 双视图产业实践是两套源或 TLM↔管脚桥；XLS 仍 experimental。

实现方案要点

  1. 前端宏记录 HIR，不把任意 Rust 子集翻译成字符串 Verilog。
  2. 阶段一：HIR→Yosys 友好 Verilog + 原生 tick 仿真 + 唯一驱动检查。
  3. 阶段二：FIRRTL 6.0 子集导出 + 托管 firtool-1.155.0。
  4. 互转：导出一级；不做 Chisel 源码往返。
  5. 多视图：functional_model 走普通 rustc；一致性用随机比对。
  6. 发布换 crate 名，并文档声明与同名项目的关系。

维度结论（压缩）

Rust eDSL 未收敛；Verilog 是跨 HDL 交换物；生产模式=宿主展开+硬件编译器；无生产级 ownership 防多驱动；CDC 用 Clash 式 phantom；不要从同一 IR 生成 TLM。

未决 / 过期

商标与抢名；仿真基准缺失。前瞻最早复查：2026-09-01（firtool 钉死）。
