# Digest: integration-interop r1-1

## Findings

**Claim:** The live FIRRTL language spec in 2026 is **chipsalliance/firrtl-spec v6.0.0** (tagged 2026-05-12). The spec repo’s release train still publishes 2.x–5.x tags; v5.0.0 is a breaking change (`{{}}` substitutions). There is no current “FIRRTL 1.x language spec” on that train. Files are supposed to start with a `FIRRTL version X.Y.Z` preamble. **Source:** [firrtl-spec releases](https://github.com/chipsalliance/firrtl-spec/releases), [v6.0.0 tag](https://github.com/chipsalliance/firrtl-spec/releases/tag/v6.0.0). **Publisher:** CHIPS Alliance / GitHub. **pub_date:** 2026-05-12 (v6.0.0); v5.0.0 listed immediately prior (2026-03-28 on the same page). **accessed:** 2026-08-18. **confidence:** high. **class:** version/compat

**Claim:** FIRRTL 6.0.0 mainly standardizes **property operations already present in Chisel and CIRCT**. The **property ABI is still unspecified / implementation-defined**; the release notes say that will be fixed later. **Source:** [firrtl-spec v6.0.0 release notes](https://github.com/chipsalliance/firrtl-spec/releases). **Publisher:** CHIPS Alliance. **pub_date:** 2026-05-12. **accessed:** 2026-08-18. **confidence:** high. **class:** version/compat | failure

**Claim:** Chisel 7’s backend was bumped to **emit `FIRRTL version 6.0.0`** (merged 2025-08-18, PR #5008). Current ChiselStage APIs emit **CHIRRTL text**, **FIRRTL dialect (MLIR)**, or **SystemVerilog via firtool** (`emitCHIRRTL` / `emitFIRRTLDialect` / `emitSystemVerilog*`). **Source:** [chisel#5008](https://github.com/chipsalliance/chisel/pull/5008); [ChiselStage 7.13.0 API](https://www.chisel-lang.org/api/latest/circt/stage/ChiselStage$.html). **Publisher:** chipsalliance / chisel-lang.org. **pub_date:** 2025-08-18 (PR); API page current as of access. **accessed:** 2026-08-18. **confidence:** high. **class:** version/compat

**Claim:** CIRCT’s FIR parser is described as a **generally complete, actively maintained implementation of the FIRRTL spec**, gated by the file’s version header (`nextFIRVersion` / `missingSpecFIRVersion` so parser and spec need not land in lock-step). It also accepts **undocumented features and the CHIRRTL flavor Chisel produces**, plus **SFC JSON annotation files**. firtool consumes **`.fir` and MLIR** (`--format=fir` / `--format=mlir`). Parse-only path documented by maintainers: `firtool -parse-only Foo.fir` or `circt-opt -import-firrtl Foo.fir`. **Source:** [FIRRTL Dialect Rationale](https://circt.llvm.org/docs/Dialects/FIRRTL/RationaleFIRRTL/); maintainer comment on [chisel#4899](https://github.com/chipsalliance/chisel/issues/4899). **Publisher:** LLVM CIRCT / chipsalliance. **pub_date:** rationale undated (live docs); issue comments 2025-04-20–22. **accessed:** 2026-08-18. **confidence:** high. **class:** version/compat | integration

**Claim:** **CHIRRTL is not a separate numbered spec.** It is Chisel’s high-level memory IR (`smem`/`cmem`/`mport`, enable/clock inference) that **must be lowered to standard FIRRTL `mem` early**. CIRCT keeps this in a **`chirrtl` dialect** (`chirrtl.combmem` / `seqmem` / `memoryport` + `memoryport.access`) because CHIRRTL types cannot sit cleanly in the FIRRTL type hierarchy, and because Chisel/stdlib **violate FIRRTL scoping** for ports declared inside `when`. CIRCT explicitly does **not** redesign CHIRRTL; it clones SFC behavior. **Source:** [FIRRTL Dialect Rationale — CHIRRTL Memories](https://circt.llvm.org/docs/Dialects/FIRRTL/RationaleFIRRTL/). **Publisher:** LLVM CIRCT. **pub_date:** live docs. **accessed:** 2026-08-18. **confidence:** high. **class:** version/compat | integration

**Claim:** **RHDL↔Chisel round-trip via FIRRTL text is not realistic on the Chisel side.** Chisel can **serialize** a circuit to FIRRTL/CHIRRTL, but **cannot parse `.fir` back into a `Circuit`**. Scala FIRRTL parsing existed last in **Chisel 3.6 / Scala FIRRTL 1.6**. **Since Chisel 5, FIRRTL compilation and parsing live in llvm/circt.** `package firrtl` APIs (including `Parser`) are **deprecated since Chisel 7.0.0**. A 2025 user with only `.fir` (no Chisel sources) was told: serialize objects (e.g. upickle), or write a **firtool pass plugin** (hooks: high FIRRTL, low FIRRTL, HW dialect, pre-Verilog). **Source:** [chisel#4899](https://github.com/chipsalliance/chisel/issues/4899) (open); [Chisel installation / SFC→MFC migration notes](https://www.chisel-lang.org/docs/appendix/migrating-from-chiseltest) via search + issue. **Publisher:** chipsalliance. **pub_date:** 2025-04-20–22. **accessed:** 2026-08-18. **confidence:** high. **class:** failure | integration

**Claim:** FIRRTL is architected as a **one-way lowering pipeline** (high/CHIRRTL → low FIRRTL → HW/Comb/Seq → Verilog), not a bidirectional HDL interchange. Spec/rationale: FIRRTL is the **elaborated Chisel circuit before simplification**; subsequent passes **remove** high-level constructs (aggregates, CHIRRTL mems, when, etc.). **Source:** [FIRRTL Dialect Rationale](https://circt.llvm.org/docs/Dialects/FIRRTL/RationaleFIRRTL/); spec.md excerpts on firrtl-spec (search-retrieved). **Publisher:** LLVM CIRCT / CHIPS Alliance. **pub_date:** live. **accessed:** 2026-08-18. **confidence:** high. **class:** integration | landscape

**Claim — where metadata dies (documented):**
1. **Annotations are not FIRRTL IR**; they are a side-channel (JSON file or CIRCT-only inline `%[…]`). They **must be consumed and removed**; leftover annotations warn (`unprocessed annotation … still remaining after LowerToHW`). Unknown annotations are treated as likely incorrect unless `--disable-annotation-unknown`.
2. **Targets are stripped** when scattered onto ops; `LowerTypes` reattaches only using remaining refs — aggregate targeting is fragile across lowering.
3. **Names:** `_`-prefixed names **may be discarded**; Chisel `_T_*` / SFC `_GEN_*` **dropped at parse**; `-O=release` / `--preserve-values=none` may delete **any** named component; `--preserve-values=named|all` keep more. Bundle lowering **mandatorily renames** (`myreg` → `myreg_a`/`myreg_b`) — this **is** the public ABI people rely on.
4. **Don’t Touch** becomes a **public symbol**; without it, wires may be bypassed (dataflow into the wire kept, through-wire not).
5. **Source locators** survive only as Verilog comments; style is a lowering option (`plain` / `wrapInAtSquareBracket` / `none`).
6. **Property ABI** (FIRRTL 6) is still implementation-defined — do not depend on it for interop.
**Source:** [FIRRTL Annotations](https://circt.llvm.org/docs/Dialects/FIRRTL/FIRRTLAnnotations/); [FIRRTL Dialect Rationale — Naming](https://circt.llvm.org/docs/Dialects/FIRRTL/RationaleFIRRTL/); [firrtl-spec v6.0.0 notes](https://github.com/chipsalliance/firrtl-spec/releases). **Publisher:** LLVM CIRCT / CHIPS Alliance. **pub_date:** live / 2026-05-12. **accessed:** 2026-08-18. **confidence:** high. **class:** failure | integration

**Claim:** Production Verilog/SV from this stack is **CIRCT `firtool`**, not Yosys and not sv2v. Chisel has used firtool since **v3.6**; Chisel 5 dropped the Scala FIRRTL Compiler. There is **no “pure Verilog vs SystemVerilog” switch**. Defaults emit **modern SV**; `--lowering-options=` dials it back. Official per-tool knobs: **Yosys** `disallowLocalVariables,disallowPackedArrays`; **Verilator** `locationInfoStyle=wrapInAtSquareBracket,disallowLocalVariables`; plus Questa/Spyglass/Vivado-specific flags. `--verilog` means “(system)verilog output,” not IEEE 1364-only. **Source:** [Verilog and SystemVerilog Generation](https://circt.llvm.org/docs/VerilogGeneration/); [Chisel versioning](https://www.chisel-lang.org/docs/appendix/versioning). **Publisher:** LLVM CIRCT / chisel-lang.org. **pub_date:** live. **accessed:** 2026-08-18. **confidence:** high. **class:** integration | pattern

**Claim:** Integrations that hurt: Yosys **cannot take default firtool SV** (no `automatic`/`logic` locals, no packed arrays). Verilator misparses location comments if paths start with `verilator` and can infer latches from `automatic logic`. Single-file firtool output (`--split-verilog` omitted) is **explicitly not a valid multi-file tool input** (separations are comments) — Bazel/cargo “one known output file” fights `--split-verilog`’s directory of `.sv` + layer includes. **Source:** [VerilogGeneration recommended options](https://circt.llvm.org/docs/VerilogGeneration/); [llvm/circt#9020](https://github.com/llvm/circt/issues/9020) (search-retrieved, firtool 1.131.0). **Publisher:** LLVM CIRCT. **pub_date:** VerilogGeneration live; #9020 recent enough to cite firtool 1.131. **accessed:** 2026-08-18. **confidence:** high (options); medium (issue 9020, search only). **class:** failure | integration

**Claim:** **sv2v** (zachjs) converts **IEEE 1800-2017 SV → IEEE 1364-2005 Verilog**, aimed at **Yosys**. Assertions are **dropped**. Yosys still chokes on some sv2v output (packed/unpacked arrays, autoblocks); workarounds like `-Ealways` appear in the tracker. This is a **post-SV Yosys adapter**, not a Chisel/FIRRTL path. If RHDL already goes through firtool, prefer **firtool lowering-options** over sv2v. **Source:** [zachjs/sv2v README](https://github.com/zachjs/sv2v/); [sv2v#314](https://github.com/zachjs/sv2v/issues/314). **Publisher:** zachjs / YosysHQ-adjacent. **pub_date:** README live; issues 2022–2024 class. **accessed:** 2026-08-18. **confidence:** medium (search snippets, not a dedicated fetch). **class:** landscape | failure

**Claim:** Yosys **can `write_firrtl`**, but CIRCT’s own CellIFT docs still tell you to **prepend `FIRRTL version 2.0.0`** before firtool — i.e. Yosys FIRRTL export is **not** spec-6/CHIRRTL Chisel output. Reverse Verilog→FIRRTL via Yosys is a **lossy side door**, not Chisel interop. **Source:** [CIRCT CellIFT Verilog flow](https://circt.llvm.org/docs/CellIFT-Verilog-Flow/) (search-retrieved). **Publisher:** LLVM CIRCT. **pub_date:** live. **accessed:** 2026-08-18. **confidence:** medium. **class:** integration | failure

**Claim:** Old **Chisel↔firtool version-skew was real and is largely fixed for Chisel 6+**, not for people who PATH-install a random firtool. Each Chisel release is **tested against one firtool**; other versions “often work, not guaranteed.” Chisel 6+ **downloads/manages firtool** (firtool-resolver / `org.chipsalliance::llvm-firtool`); override with **`CHISEL_FIRTOOL_PATH`**. Docs also recommend **emit `.fir` and invoke firtool from your own build**. Remaining pain: **NixOS / old glibc** cannot use the prebuilt binary (build from source); **Bazel** (and analogously cargo) that pin Chisel and firtool independently still skew (e.g. printf / `$SimulationTime` split between firtool 1.111.0 vs 1.111.1). Chisel 5 required a **manual PATH binary** (e.g. 1.40.0 for Chisel 5.0.0) — that class of bug is closed in 6.0.0. **Source:** [Chisel versioning](https://www.chisel-lang.org/docs/appendix/versioning) (example pin `llvm-firtool` **1.153.0**); [Installation — Firtool](https://www.chisel-lang.org/docs/installation); [chisel#3277](https://github.com/chipsalliance/chisel/issues/3277); [chisel#3608](https://github.com/chipsalliance/chisel/issues/3608) (closed 2024-01-27: “Chisel 6.0.0 manages firtool”). **Publisher:** chisel-lang.org / chipsalliance. **pub_date:** versioning/install live; issues 2023–2024, still the cited fix. **accessed:** 2026-08-18. **confidence:** high. **class:** version/compat | pattern | failure

**Claim:** Chisel 7.x versioning **page has a 7.x firtool table behind a tab**; the fetched HTML only materialized the **5.x/3.x tables** (5.0.0→firtool 1.40.0; 5.1–5.3→1.43.0; 3.6.x→1.37.0) plus the **1.153.0** override example. Installation documents querying `chisel3.BuildInfo.firtoolVersion` (example Chisel **7.2.0**). **Do not invent a 7.x↔firtool pairing beyond 1.153.0-as-documented-example.** **Source:** [Versioning](https://www.chisel-lang.org/docs/appendix/versioning); [Installation](https://www.chisel-lang.org/docs/installation). **Publisher:** chisel-lang.org. **pub_date:** live. **accessed:** 2026-08-18. **confidence:** high (limitation of the fetch). **class:** version/compat

**Claim — cargo-like HDL pattern (Rust eHDL, not Chisel):** Cement/cmt2 (`cmtc` crate) generates FIRRTL then **shells out to firtool on PATH**, with a **hard-pinned tarball** (`firtool-1.86.0` from llvm/circt releases) and separate Verilator/ksim installs (ksim even requires **renaming** `firtool`→`firtool-ksim`). That pin is **far behind** current CIRCT tutorial firtool (**1.147.0** in a 2026 tutorial repo) and Chisel’s **1.153.0** Maven example — the packaging failure mode for cargo HDLs is **unmanaged/stale firtool**, not missing crates.io bindings. **Source:** [pku-liang/Cement README](https://github.com/pku-liang/Cement/blob/cmt2/README.md) / [crates.io/cmtc](https://crates.io/crates/cmtc); [cowardsa/CIRCT_TUTORIAL_2026](https://github.com/cowardsa/CIRCT_TUTORIAL_2026). **Publisher:** PKU Liang / CIRCT tutorial. **pub_date:** README live; tutorial 2026. **accessed:** 2026-08-18. **confidence:** medium (search, not dedicated fetch). **class:** pattern | failure

**Claim:** Verilator is the **documented Chisel sim backend** (transpile to C++14). Distro packages are often **too old**; Windows guidance is **Yosys OSS CAD Suite + MinGW**, not a single binary. Same class of pain a cargo HDL will hit if it assumes `apt install verilator`. **Source:** [Chisel installation — Verilog Simulation](https://www.chisel-lang.org/docs/installation). **Publisher:** chisel-lang.org. **pub_date:** live. **accessed:** 2026-08-18. **confidence:** high. **class:** pattern

## Leads worth chasing

- `chipsalliance/firtool-resolver` + Maven `org.chipsalliance:llvm-firtool` as the **pattern to copy** for a Rust crate (download pinned CIRCT tarball; do not trust system firtool).
- firtool **pass-plugin insertion points** (high/low FIRRTL, HW, pre-SV) if RHDL needs Chisel-adjacent transforms without Chisel parse.
- Whether **Yosys `write_firrtl`** still emits pre-3.0 syntax (`<=` connects, string hex lits) vs spec 3.0+ `connect` / `UInt(0h…)`.
- **FIRRTL ABI spec** (`abi.md` / abi.pdf on v6.0.0) for name/port-lowering interop — fetched only in passing.
- CIRCT **`--split-verilog` vs Bazel/cargo output declaration** (circt#9020).
- Property operations: usable in Chisel/CIRCT, **not ABI-stable** for a second frontend.

- Official **firtool `--help`** this run (not executed); input formats inferred from CIRCT docs + maintainer comments.
- **Chisel 7.x ↔ firtool version table** in fetched HTML (tab not expanded); only 3.6/5.x tables + `llvm-firtool` 1.153.0 example.
- Documented **RHDL↔Chisel** round-trip, or FIRRTL as a lossless bidirectional format.
- **Performance/scale** numbers for firtool vs SFC (none retrieved).
- A crates.io **firtool-resolver equivalent** with the freshness of Chisel 6+; Rust examples pin stale tarballs.
- Confirmation that **old version-skew bugs remain open** for Chisel 6+/7 — tracker evidence says **fixed via managed firtool**; residual skew is **self-managed Bazel/PATH/Nix**.
