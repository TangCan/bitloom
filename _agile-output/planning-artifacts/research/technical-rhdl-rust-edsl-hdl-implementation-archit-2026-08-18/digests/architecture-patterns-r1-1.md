# Digest: architecture-patterns r1-1

## Findings

**Proc-macro / quote eDSLs, staged host-language generators, and standalone compilers all exist; production scale sits with staged generators plus a separate hardware compiler, not with kernel-translating proc-macros.** RustHDL is a proc-macro eDSL: `#[derive(LogicBlock)]` plus `#[hdl_gen]` on `fn update(&mut self)` translate a synthesizable Rust subset to Verilog after `rustc` has type-checked the kernel. **Source:** rust-hdl crate docs. **Publisher:** docs.rs / Samit Basu. **pub_date:** live crate docs (retrieved this run). **accessed:** 2026-08-18. **confidence:** high. **class:** pattern | implementation.

**That proc-macro kernel pattern fails first on expressiveness, then on scale of simulation, not on a documented compile-time blowup.** rust-hdl kernels: must remain valid Rust; `.next` is write-only; function calls are a tiny allow-list ignored in HDL; arrays/`for` loops are “still pretty restrictive”; C-style `match` only. **Source:** rust-hdl crate docs, sections on Signals / kernels / loops. **Publisher:** docs.rs. **pub_date:** live. **accessed:** 2026-08-18. **confidence:** high. **class:** failure | implementation.

**The successor project states the same architecture failed to deliver “just Rust,” reuse, enum payloads, and fast sim — and names proc-macros as a design risk.** RHDL’s README: rust-hdl was “structured patterns to help you write hierarchical strongly typed Verilog”; users had to remember `.val()`/`.next`, local signals for temps, and awkward inter-module wiring; only C-style enums; sim became limiting as designs grew (“1 to 2 orders of magnitude” faster in RHDL). Explicit risk: “Procedural macros have some severe limitations, including the inability to share state between them and the lack of context for the processing.” **Source:** https://raw.githubusercontent.com/samitbasu/rhdl/main/README.md . **Publisher:** GitHub / Samit Basu. **pub_date:** live README (retrieved 2026-08-18). **accessed:** 2026-08-18. **confidence:** high. **class:** failure | pattern. *Two-source with rust-hdl docs above for the `.val`/`.next` / subset claim; two-source with rust-hdl README below for the rewrite/abandonment of the old crate.*

**Active development left rust-hdl; the old crate is a rewrite-in-progress, not a maintained frontend.** rust-hdl README: rename to `rhdl`, “rebuilding this project from scratch,” new work in the `rhdl` repo, then archive rust-hdl. Fielded commercial firmware existed on rust-hdl; RHDL README says that sponsorship ended (schedule risk). Widget library and FPGA BSPs are still unchecked on RHDL’s plan. **Source:** https://raw.githubusercontent.com/samitbasu/rust-hdl/master/README.md plus RHDL README. **Publisher:** GitHub / Samit Basu. **pub_date:** live READMEs. **accessed:** 2026-08-18. **confidence:** high. **class:** failure | landscape. *Two independent URLs, same author; treat as one lineage, not two independent orgs.*

**Staged metaprogramming (Chisel/Spinal style) is the production pattern: host code elaborates a graph, then a compiler lowers it.** Chisel: frontend `chisel3.*` → `Builder` global state → `chisel3.firrtl.*` IR → `Emitter` writes a FIRRTL file; `firrtl` crate is “vestigial remains of the old Scala FIRRTL compiler.” Powered by FIRRTL + LLVM CIRCT. **Source:** chipsalliance/chisel README (GitHub search retrieval). **Publisher:** CHIPS Alliance. **pub_date:** live README. **accessed:** 2026-08-18. **confidence:** high. **class:** pattern | implementation.

**SpinalHDL is the same staged pattern without a public FIRRTL-like interchange: Scala library calls build an in-memory netlist, then passes flush VHDL/Verilog.** Docs: “not a language: it’s a regular Scala library”; “Scala is for elaboration, SpinalHDL for hardware description”; Scala `for` unrolls into RTL. **Source:** SpinalHDL “Interaction” docs, https://spinalhdl.github.io/SpinalDoc-RTD/v1.8.0/SpinalHDL/Getting%20Started/Scala%20Guide/interaction.html . **Publisher:** SpinalHDL project. **pub_date:** docs labeled v1.8.0. **accessed:** 2026-08-18. **confidence:** high. **class:** pattern.

**Clash is a standalone compiler (Haskell → HDL), not a proc-macro eDSL.** `Signal (dom :: Domain) a` is a compiler-checked synthesis domain. **Source:** clash-prelude 1.8.5 `Clash.Signal`. **Publisher:** Hackage / QBayLogic B.V. (copyright 2021–2026). **pub_date:** package 1.8.5 docs. **accessed:** 2026-08-18. **confidence:** high. **class:** pattern | version/compat.

**A second 2026-era Rust eDSL (hdl-cat) copies the RHDL *shape* (bits + IR + sim + Verilog) but still uses a `#[kernel]` proc-macro over a tiny subset (bool / `Bits<N>` / `SignedBits<N>`, lets, binary ops, `!`).** Clock-domain phantoms live in `Signal<D, T>`. Explicitly “conceptually parallel to RHDL.” **Source:** https://github.com/MavenRain/hdl-cat and crates.io/hdl-cat-macros. **Publisher:** GitHub / crates.io. **pub_date:** live (retrieved 2026-08-18). **accessed:** 2026-08-18. **confidence:** medium (no independent evaluation). **class:** landscape | implementation.

**cmtrs is a third Rust proc-macro pattern: Bluespec-like rules/methods inside `#[module]`, including `external!(..., firrtl_string)`.** That is host-side recording + FIRRTL text, not rustc-subset translation. **Source:** https://docs.rs/cmtrs/latest/cmtrs/ . **Publisher:** docs.rs. **pub_date:** live. **accessed:** 2026-08-18. **confidence:** medium. **class:** pattern | implementation.

**Production Chisel does *not* emit CIRCT MLIR from the frontend. It emits FIRRTL (CHIRRTL) text; CIRCT’s FIRRTL dialect is a drop-in replacement for the Scala FIRRTL Compiler (SFC).** CIRCT rationale: dialect “follows the FIRRTL IR specification and the SFC implementation almost exactly”; supports CHIRRTL from Chisel and SFC annotations; parser is “generally complete” and “actively maintained.” **Source:** https://circt.llvm.org/docs/Dialects/FIRRTL/RationaleFIRRTL/ . **Publisher:** LLVM CIRCT. **pub_date:** live compiler docs. **accessed:** 2026-08-18. **confidence:** high. **class:** pattern | implementation.

**Chisel’s current Verilog path is firtool (CIRCT), version-pinned per Chisel release.** “Starting with Chisel v3.6, Chisel uses firtool (part of the LLVM CIRCT project) to generate Verilog.” Docs show `llvm-firtool` 1.153.0 as the example pin; a given Chisel is “only tested against the version listed.” API surface in 7.13.0/7.14.0 is `circt.stage.{ChiselStage, FirtoolOption, FirtoolBinaryPath}`. **Source:** https://www.chisel-lang.org/docs/appendix/versioning plus https://www.chisel-lang.org/api/latest/circt/stage/index.html (7.14.0). **Publisher:** chisel-lang.org / CHIPS Alliance. **pub_date:** live docs (Chisel 7.x tables present; 7.14.0 API). **accessed:** 2026-08-18. **confidence:** high. **class:** version/compat. *Two-source: versioning page + 7.14.0 API. Issue https://github.com/chipsalliance/chisel/issues/3277 : Chisel 3.6.0 published against firtool 1.37.0; Chisel 6.0.0 uses firtool-resolver so Chisel manages the binary — old PATH pain is fixed.*

**Emitting “MLIR-native” FIRRTL that diverges from the spec was tried and rolled back.** CIRCT rationale: early dialect “made heavy deviations from FIRRTL IR and the SFC (see the Type Canonicalization section)”; “elegant” deviations “led to difficult to resolve mismatches with the SFC and the inability to verify FIRRTL IR.” Remaining deviations are small, to use MLIR multi-result ops (e.g. `firrtl.instance`). **Source:** CIRCT FIRRTL Dialect Rationale (same URL). **Publisher:** LLVM CIRCT. **accessed:** 2026-08-18. **confidence:** high. **class:** failure | pattern. *Second source: LLVM Discourse thread “FIRRTL dialect rationale doc” (https://discourse.llvm.org/t/firrtl-dialect-rationale-doc/2485) — authors discuss diverging for MLIR-native instances and type canonicalization vs SFC.*

**SFC scale pain was real; CIRCT was the production answer, not “frontend emits MLIR.”** WOSET 2021: “large designs based on Chisel which may take an hour or more to finish compilation of their FIRRTL IR”; CIRCT claimed “order-of-magnitude improvement in FIRRTL compilation times for SiFive designs.” **Source:** Izraelevitz et al., “MLIR as Hardware Compiler Infrastructure,” WOSET 2021, https://woset-workshop.github.io/PDFs/2021/a06.pdf . **Publisher:** WOSET workshop. **pub_date:** 2021. **accessed:** 2026-08-18. **confidence:** medium (age >2y; numbers not re-measured this run). **class:** landscape. *Two-source class for scale: pair with CIRCT rationale + Chisel 7 firtool path confirming the architectural replacement stuck. Do not treat 2021 “hour+” as a 2026 number.*

**Custom HIR (not FIRRTL, not CIRCT) is what RHDL actually built.** Plan items marked done: “hardware-compatible intermediate representation (RHIF)”; bootstrap AST→RHIF compiler; SSA; RHIF→Verilog; then “an intermediate RTL layer to bridge differences between HDLs and RHIF”; Verilog string emit replaced with a “proper AST.” Not on the list: emit CIRCT/MLIR. **Source:** RHDL README. **Publisher:** GitHub / Samit Basu. **accessed:** 2026-08-18. **confidence:** high. **class:** implementation | pattern.

**No production Rust HDL was found that uses Rust ownership / affine / linear types to forbid multiple drivers.** Searches this run for “linear types hardware description” and “multiple drivers HDL type system” surfaced CirQTS (Idris2) and vendor DRC, not a Rust ownership encoding.

**The real paper on linear/quantitative wiring is CirQTS (ECOOP 2023), retrofitting SystemVerilog *netlists*, not a Rust eDSL.** Claim: structural types still allow unused ports, dangling wires, fan-in/fan-out; QTT makes “wires and ports used once” intrinsic; `split`/`collect` primitives weaken linearity explicitly. Mechanized in Idris2; can type-check existing Verilog netlists (modulo restrictions). **Source:** de Muijnck-Hughes & Vanderbauwhede, “Wiring Circuits Is Easy as {0,1,ω}, or Is It…,” ECOOP 2023, DOI 10.4230/LIPIcs.ECOOP.2023.8 . **Publisher:** Schloss Dagstuhl LIPIcs. **pub_date:** 2023. **accessed:** 2026-08-18. **confidence:** high. **class:** pattern.

**Outcomes of that linearization: it works, and it is too strict for normal RTL without extra wires.** Half-adder: non-linear 2 gates / 0 internal wires vs linear 4 gates / 4 wires (`split` on each input). Benchmark table (FlipFlopD, FullAdder, HalfAdder, Mux21) shows more wires and gates in the linear column. Authors: “sometimes linear usage is too restrictive and dependent on the intended behaviour”; “open question over how best we can weaken linearity in more nuanced ways.” They explicitly punt promoting QTT *up* the synthesis chain to a full HDL. **Source:** same ECOOP 2023 paper, §5–7 and benchmarking table. **Publisher:** Dagstuhl. **pub_date:** 2023. **accessed:** 2026-08-18. **confidence:** high. **class:** failure | implementation. *Paper is >2y old; no 2025–2026 follow-on implementation in Rust found this run.*

**Hardcaml prevents multiple drivers at elaboration, not via linear types.** “During elaboration, Hardcaml enforces that there are no floating wires, no multiple drivers, and that connected signals have matching widths.” **Source:** Hardcaml wiki “Arxiv Paper” page, https://ocamlstreet.gitbook.io/hardcaml-wiki/hardcaml/arxiv-paper . **Publisher:** OCaml Street / Hardcaml wiki (summarizing Jane Street Hardcaml). **pub_date:** live wiki (retrieved 2026-08-18). **accessed:** 2026-08-18. **confidence:** medium (secondary wiki, not the arXiv PDF). **class:** implementation.

**Typed clock domains work in Clash in practice: `Signal dom a` will not compose across `dom` without an explicit (usually `unsafe*`) primitive.** Domain config includes period (ps), edge, reset kind, init behavior, polarity; `createDomain` / `KnownDomain`; defaults `System` / `XilinxSystem` / `IntelSystem`. **Source:** clash-prelude 1.8.5 `Clash.Signal`. **Publisher:** Hackage / QBayLogic. **pub_date:** 1.8.5 (copyright through 2026). **accessed:** 2026-08-18. **confidence:** high. **class:** pattern | version/compat.

**Clash CDC is typed at the boundary and *unsafe* in the wire:** `unsafeSynchronizer` “must be used to connect one clock domain to the other, and will be synthesized to a (bundle of) wire(s)”; “only be used as part of a proper synchronization component.” Library wrappers: `dualFlipFlopSynchronizer` (bit) and `asyncFIFOSynchronizer` (word; needs tool skew/max-delay on gray pointers). **Source:** clash-prelude 1.8.5 `Clash.Explicit.Signal` + `Clash.Explicit.Synchronizer` Haddock/source. **Publisher:** Hackage / QBayLogic. **accessed:** 2026-08-18. **confidence:** high. **class:** implementation.

**Clash’s type-level domain is not a full physical-clock uniqueness proof.** Same-`dom` `Clock`/`Reset` values “could hence be connected to completely unrelated clock sources” (explicit clocks) and still type-check — metastability caveat is documented, not solved. **Source:** clash-prelude 1.8.5 `Clash.Explicit.Signal` “Explicit clocks and resets, and meta-stability.” **Publisher:** Hackage / QBayLogic. **accessed:** 2026-08-18. **confidence:** high. **class:** failure | pattern.

**Chisel `withClock` / `withClockAndReset` is dynamic scoping of the implicit clock, not a typed domain on `Data`.** Docs: wrap `RegNext` / `Module(...)` to change which clock new sequential elements use. “To cross clock domains safely, you will need appropriate synchronization logic (such as an asynchronous FIFO). You can use the AsyncQueue library.” No type error for wiring `io.stuff` into both domains in the official example. **Source:** https://www.chisel-lang.org/docs/explanations/multi-clock . **Publisher:** chisel-lang.org. **pub_date:** live “Chisel 3” docs. **accessed:** 2026-08-18. **confidence:** high. **class:** pattern | implementation. *API still current: chisel 7.11.0/7.13.0 `chisel3.withClock`.*

**Hardcaml has CDC *utilities*, not typed domains.** `Hardcaml.Clocking` is `{clock; clear}` plus `Cdc.stretch`, `with_valid_pulse_detect_rising_edge`, `reg_no_clear_with_async_reg_annotation` (Vivado `async_reg`). Wiki future work: “Currently, Hardcaml uses a single `Signal.t` type… We *plan* to constrain `Signal.t` to specific clock domains using phantom types.” **Source:** Hardcaml v0.17.1 `Clocking` / `Clocking.Cdc` docs + wiki “Future Work.” **Publisher:** Jane Street Hardcaml docs / wiki. **pub_date:** v0.17.1 docs + live wiki. **accessed:** 2026-08-18. **confidence:** high that phantoms are not shipped in the cited docs. **class:** landscape | implementation. *Check-if-fixed: as of these docs, not fixed.*

**Bluespec’s working CDC check is compiler-side, per rule/method, not a phantom type on wires.** BSC: illegal clock crossing **G0007** if a rule/method mixes method calls from different clock domains; at most one reset or **G0043**. Positions were historically useless; `-cross-info` was the workaround (KPNS #026). **Source:** Bluespec SystemVerilog Known Problems and Solutions, rev. 24 Nov 2008, https://web.ece.ucsb.edu/its/bluespec/doc/BSV/kpns.pdf . **Publisher:** Bluespec, Inc. **pub_date:** 2008-11-24. **accessed:** 2026-08-18. **confidence:** high for the check existing; low that 2008 diagnostics are still the 2026 UX. **class:** pattern | failure.

**RHDL’s intended clock story is top-level and analysis-based, not Clash-style `Signal dom a`.** “State advancement is handled at the top level, where things like clock crossings are also dealt with”; plan item checked: “Add logic to identify and flag clock crossings.” **Source:** RHDL README. **Publisher:** GitHub / Samit Basu. **accessed:** 2026-08-18. **confidence:** medium (plan checkbox, not a published CDC semantics paper). **class:** implementation.

**hdl-cat documents clock-domain phantoms (`Signal<D, T>`) as a Clash-like encoding in Rust types.** **Source:** hdl-cat README / crates.io description. **Publisher:** GitHub / crates.io. **accessed:** 2026-08-18. **confidence:** medium (library claim, no eval). **class:** landscape.

**kaze (Rust embedded HDL, graph API → Rust sim or Verilog) last published 0.1.19 on 2021-03-14.** **Source:** https://crates.io/crates/kaze (Updated: 2021-03-14T18:08:42Z) and GitHub compare showing 0.1.19 changelog dated 2021-03-14. **Publisher:** crates.io / GitHub (Jake “ferris” Taylor). **pub_date:** 2021-03-14. **accessed:** 2026-08-18. **confidence:** high for last-release date; do **not** upgrade that to “archived” without a second explicit archive notice (not retrieved). **class:** landscape | failure. *Two-source for last-activity date.*

**ChiselTest / SFC coupling broke when Chisel 5 switched Verilog gen to firtool.** Tywaves wiki: “Starting from version 5, Chisel replaced its hardware compiler with `firtool`… ChiselTest… is built around the Scala FIRRTL Compiler (SFC), which made difficult the support in Chisel 5… ChiselSim has been created as a replacement.” **Source:** https://github.com/rameloni/tywaves-chisel/wiki/Tywaves-internals . **Publisher:** GitHub wiki (third party, but describes upstream ChiselSim). **accessed:** 2026-08-18. **confidence:** medium. **class:** failure. *Check-if-fixed: ChiselSim is the documented replacement; SFC remains vestigial in the Chisel README.*

**sifive/chisel-circt (historical): MFC was “feature complete” but “does not support every annotation and custom transform-backed extension.”** That gap is why SFC lingered as backup (Chipyard: SFC when Fixed types or custom FIRRTL passes). **Source:** https://github.com/sifive/chisel-circt README; Chipyard Firrtl-Transforms docs. **Publisher:** SiFive / Chipyard. **accessed:** 2026-08-18. **confidence:** medium (chisel-circt is the *old* integration crate; Chisel 6+ in-trees firtool). **class:** version/compat | landscape.

- **Proc-macro compile-time blowup** numbers or GitHub issues for rust-hdl / RHDL / hdl-cat (compile-time minutes, rustc memory). RHDL names proc-macro *semantic* limits (no shared state, no context), not compile-time cost.
- Independent post-mortems of rust-hdl from a second organization (only author READMEs + rust-hdl docs).
- Evidence that kaze is officially archived (only last crates.io release 2021-03-14).

- Hardcaml phantom-typed clock domains as shipped API (docs still describe a plan).
- Clash-equivalent typed CDC in Chisel (docs still recommend AsyncQueue; `withClock` is a scope).
- Scale numbers ≤12 months for FIRRTL/CIRCT compile times (only 2021 WOSET “hour+” / “10×”).
